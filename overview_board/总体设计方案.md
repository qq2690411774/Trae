# 部门看板系统设计方案

## 一、需求分析

### 1.1 数据来源分析

| 数据源 | 系统名称 | 主要数据内容 | 数据格式 |
|--------|----------|--------------|----------|
| 软件过程管理 | spif系统 | 所属项目、工作类型、开始/截止时间、工作性质 | 数据库 |
| 项目计划执行 | MS Project | 项目计划、进度跟踪、资源分配 | MPP/XML |
| 项目计划执行 | Excel表格 | 项目计划、执行跟踪 | XLSX |
| 缺陷管理 | 禅道 | 缺陷记录、状态、优先级 | 数据库 |

### 1.2 部门痛点分析

| 痛点 | 根因 | 解决思路 |
|------|------|----------|
| 无法快速了解各产品线研发投入占比和产出效能 | 数据分散，缺乏聚合分析 | 建立产品线维度Dashboard |
| 项目进度分散在多个工具中，缺乏全局视野 | Project与Excel数据不互通 | 统一数据归集平台 |
| 人员利用率不清晰 | spif数据未与资源关联 | 人力投入热力图 |
| 非功能性工作难以量化 | 缺乏分类统计 | 工作类型分类统计 |

### 1.3 员工痛点分析

| 痛点 | 解决思路 |
|------|----------|
| 不清楚自己在整体目标中的位置 | 目标对齐视图 |
| 跨团队信息不对称 | 团队工作概览 |
| 个人贡献难以量化 | 个人贡献报表 |

## 二、系统架构设计

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    前端展示层                            │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐        │
│  │部门总览 │ │项目进度 │ │人员效能 │ │个人工作 │        │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘        │
└─────────────────────────────────────────────────────────┘
                           │
┌─────────────────────────────────────────────────────────┐
│                    数据服务层                            │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐        │
│  │数据归集 │ │数据清洗 │ │数据分析 │ │数据可视化│        │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘        │
└─────────────────────────────────────────────────────────┘
                           │
┌─────────────────────────────────────────────────────────┐
│                    数据源层                              │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐         │
│  │ spif │ │Project│ │Excel │ │禅道  │ │手工填│         │
│  └──────┘ └──────┘ └──────┘ └──────┘ └──────┘         │
└─────────────────────────────────────────────────────────┘
```

### 2.2 关键数据结构

#### 2.2.1 项目主数据表
- 项目ID、项目名称、产品线、项目经理
- 开始日期、计划结束日期、实际结束日期
- 项目状态、优先级
- 计划工时、实际工时

#### 2.2.2 人员主数据表
- 员工ID、姓名、所属团队、岗位
- 入职日期、职级

#### 2.2.3 工作日志表(spif数据)
- 日志ID、员工ID、项目ID
- 工作类型、工作描述
- 开始时间、结束时间
- 工作时长、工作性质(功能/缺陷/技术债/会议等)

#### 2.2.4 缺陷数据表(禅道数据)
- 缺陷ID、所属项目、严重程度
- 发现时间、修复时间、关闭时间
- 缺陷状态、所属模块

### 2.3 数据归集方法

| 数据源 | 归集方式 | 频率 | 说明 |
|--------|----------|------|------|
| spif | API/数据库直连 | 每日 | 读取工作日志 |
| Project | 文件导入 | 每周 | 导入MPP/XML文件 |
| Excel | 文件导入 | 每周 | 导入XLSX模板 |
| 禅道 | API/数据库直连 | 每日 | 同步缺陷数据 |

## 三、主要模块设计

### 3.1 后台模块

1. **数据源管理**
   - 数据源配置
   - 导入任务调度
   - 数据校验

2. **数据清洗**
   - 规则引擎
   - 数据映射
   - 异常处理

3. **分析引擎**
   - 维度计算
   - 指标聚合
   - 报表生成

### 3.2 前端模块

1. **部门总览Dashboard**
   - 产品线投入占比(饼图)
   - 月度工作量趋势(折线图)
   - 关键指标卡片

2. **项目进度中心**
   - 项目列表(含进度条)
   - 项目详情视图
   - 风险预警

3. **人员效能分析**
   - 人员利用率热力图
   - 团队工作分布
   - 产能分析

4. **个人工作台**
   - 我的任务
   - 我的贡献
   - 目标对齐
